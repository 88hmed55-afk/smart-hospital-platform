## 2. الفكرة المعمارية في سطر واحد

> **تطبيق مؤسسي واحد (EAR) يُنشر على خادم واحد داخل المستشفى، بواجهة React تُخدَم من نفس الأصل، ومنطق أعمال كامل داخل EJB، وقاعدة MySQL مركزية واحدة، مع محرك تحليلات وقرارات يعمل على نفس البيانات ولا ينفّذ أي قرار حساس دون موافقة بشرية.**

```
متصفحات الأقسام (LAN)
        │ HTTPS + Cookie Session + CSRF
        ▼
┌──────────────────────────── GlassFish 7 (خادم مركزي) ────────────────────────────┐
│  smart-hospital-ear                                                              │
│  ├── smart-hospital-war    React build + /api/v1 + Filters + SSE                 │
│  └── smart-hospital-ejb    EJB Services + JPA + JTA + JMS + Timer + Analytics     │
│                                   │ JNDI DataSource (pool)                        │
└───────────────────────────────────┼──────────────────────────────────────────────┘
                                    ▼
                        MySQL 8.0.38 (قاعدة واحدة مركزية)
```

## 4. أهم 10 قرارات هندسية اتُخذت (ملخص ADR)

| ADR | القرار | لماذا |
|---|---|---|
| ADR-001 | Modular Monolith داخل EAR واحد | يطابق متطلباتك، ويقلل التعقيد التشغيلي في مستشفى بخادم واحد |
| ADR-002 | حدود وحدات صارمة بالحزم + واجهات خدمة فقط | يمنع "الكرة الطينية" ويسمح بالفصل مستقبلًا |
| ADR-003 | مصادقة بجلسة على الخادم (Cookie) لا JWT | نفس الأصل، إبطال فوري، لا تخزين توكن في المتصفح |
| ADR-004 | PBKDF2WithHmacSHA256 (JDK) بدل Argon2id | صفر اعتماديات إضافية، متوافق مع JDK 17، مع مسار ترقية |
| ADR-005 | Transactional Outbox من اليوم الأول | لا فقد إشعار ولا فقد عملية طبية |
| ADR-006 | SSE للتحديث الفوري + Polling احتياطي | أبسط من WebSocket وأكفأ من Polling الدائم |
| ADR-007 | مفاتيح عامة ULID بجانب PK رقمي | لا كشف تسلسل السجلات، ودعم Idempotency والتكامل |
| ADR-008 | قفل متفائل + قفل متشائم انتقائي (FEFO/الأسرة) | يمنع الازدواج تحت التزامن دون خنق النظام |
| ADR-009 | سجل تدقيق بسلسلة Hash قابلة للتحقق | يجعل التلاعب قابلاً للاكتشاف |
| ADR-010 | التحليلات على جداول Snapshot يومية لا استعلامات ثقيلة مباشرة | تقارير سريعة لا تُجمّد الواجهة |

باقي القرارات في `architecture/08-adr.md`.

## 5. ما أضفته إلى مشروعك بعد البحث المقارن

قارنت مشروعك مع OpenMRS، Bahmni، OpenEMR، GNU Health، HospitalRun، OpenELIS، Medplum/FHIR، وأنظمة HIS التجارية. الفجوات الحقيقية لم تكن في "الشاشات"، بل في **الطبقة السريرية الدقيقة** و**الحوكمة** و**جودة البيانات**.

أهم 12 إضافة مقترحة (التفصيل في `requirements/13-smart-features-catalog.md`):

1. **EMPI / Patient Identity Resolution** — كشف تكرار المرضى بدرجة تشابه، لا بالاسم فقط.
2. **Closed-Loop Medication Administration (BCMA)** — مسح باركود المريض والدواء والدفعة قبل الإعطاء.
3. **NEWS2 / Early Warning Score قابل للتهيئة** — تنبيه تدهور حالة المريض من العلامات الحيوية.
4. **Specimen Chain-of-Custody + TAT** — تتبّع العينة من السحب حتى الاعتماد وقياس زمن الدورة.
5. **Order Sets & Clinical Templates** — تقليل الإدخال اليدوي وتوحيد التوثيق.
6. **Drug–Allergy / Drug–Drug Interaction Checks** — تحقق غير معطِّل عند الوصف، بقواعد قابلة للتهيئة.
7. **Surgical Safety Checklist + OR Utilization** — قائمة سلامة العمليات وقياس كفاءة غرف العمليات.
8. **Bed Board + Housekeeping/Transport States** — لا يكفي "السرير مشغول"؛ يجب معرفة "قيد التنظيف" و"بانتظار نقل".
9. **Discharge Summary + Follow-up** — إغلاق الحلقة السريرية بعد الخروج.
10. **Quality & Safety (Incident Reporting, HAI surveillance)** — وحدة جودة حادثة وعدوى مكتسبة.
11. **Data Quality Dashboard** — اكتمال البيانات، تناقض التواريخ، سجلات بلا تشخيص.
12. **Tamper-evident Audit + Break-Glass Review** — تدقيق غير قابل للتحريف ومراجعة الوصول الاستثنائي.

وأضفت **محرك قرارات تشغيلية** بست قواعد جاهزة (DR-001..DR-006) مع قياس أثر فعلي بعد التنفيذ، بدل "AI" بلا تفسير.

## 8. نطاق النسخة الأكاديمية (مقترح)

**يدخل:** إعدادات المنصة، المرضى، المواعيد، الاستقبال، الزيارة والسجل الطبي، المختبر، الصيدلية، التنويم والأسرة، الفواتير والمدفوعات، الصلاحيات والتدقيق، الإشعارات، التقارير، KPIs وبطاقات القرار.

**يخرج (مصمّم لا منفّذ):** الأشعة الكاملة، غرف العمليات، الموارد البشرية الكاملة، التأمين، Blood Bank، بوابة المريض، Telemedicine، FHIR/DICOM، Multi-branch، HA.

هذا القصّ مقصود: **نظام صغير مكتمل ومُختبَر** أقوى أكاديميًا وهندسيًا من نظام ضخم ناقص.
