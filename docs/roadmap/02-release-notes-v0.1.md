### 2.2 امتداد مشروط — يُنفّذ إن سمح الجدول

### 2.3 تصميم فقط — لا تنفيذ إنتاجي

| النطاق | يُسلَّم | لا يُسلَّم |
|---|---|---|
| RAD | ERD، API، حالات، قوالب تقارير | شاشات إنتاجية، PACS، DICOM |
| ORS | ERD، API، حالات، قائمة سلامة قابلة للتهيئة | جدولة عمليات فعلية |
| HRM | ERD مبسّط، بيانات طبيب/ترخيص | رواتب، حضور، تقييم أداء |
| INT | Adapter، جداول رسائل، معرفات خارجية | أي ادعاء توافق FHIR/HL7 |

### 2.4 خارج النطاق نهائيًا في v1

- Blood Bank.
- بوابة المريض وTelemedicine.
- تطبيق موبايل أصلي (متصفح متجاوب فقط).
- التأمين والمطالبات (نقدي فقط).
- Multi-branch الكامل (حقل `branch_id` جاهز بلا منطق توزيع).
- HA/Clustering (خادم واحد + نسخ + RTO).
- Offline-first أو قاعدة بيانات محلية على الأجهزة.
- AI تشخيصي أو جرعات آلية.
- التوقيع الإلكتروني المعتمد قانونيًا.
- الفوترة الإلكترونية الحكومية.
- تكامل FHIR/HL7/DICOM رسمي.

## 4. القيود المعروفة (Known Limitations)

| # | القيد | الأثر | التخفيف/الخطة |
|---|---|---|---|
| L-01 | خادم واحد، لا HA | توقف عند فشل العتاد | UPS + نسخ + RTO ≤ 4h؛ HA في v2 |
| L-02 | نقدي فقط، لا تأمين | لا مطالبات | حقول `payer_type` جاهزة؛ v2 |
| L-03 | لا تكامل FHIR/HL7/PACS | لا تبادل خارجي | Adapter معزول؛ لا ادعاء توافق |
| L-04 | لا BCMA بأجهزة مخصصة | الاعتماد على باركود المتصفح/الماسح | دعم ماسح USB؛ أجهزة في v2 |
| L-05 | التوقعات بسيطة (Seasonal Naive/MA/Croston/Linear) | دقة محدودة | WAPE موثّق؛ لا قرار آلي |
| L-06 | لا AI تشخيصي | لا دعم تشخيص | خارج النطاق بقرار ADR-020 |
| L-07 | بيانات وهمية فقط | لا قيمة إنتاجية | مولّد 12 شهرًا؛ ETL في v1.1 |
| L-08 | MFA اختياري | حسابات مديرين بلا عامل ثانٍ إن لم تُفعّل | تفعيل سياسة للأدوار الحساسة |
| L-09 | RTL/إنجليزي، لا لغات أخرى | قيد استخدام | قاموس مركزي قابل للتوسعة |
| L-10 | مستشفى واحد | لا تقارير موحّدة | `branch_id` جاهز |
| L-11 | الاحتفاظ 10 سنوات طبي/5 مالي افتراض | قد يخالف قانونًا محليًا | تأكيد قانوني قبل الإنتاج (PD-012) |
| L-12 | لا توقيع إلكتروني معتمد قانونيًا | التوقيع داخلي فقط | سجل تدقيق + توقيع داخلي |
| L-13 | لا اختبار اختراق رسمي | لا شهادة أمنية | ZAP + مراجعة؛ اختبار خارجي في v1.1 |
| L-14 | لا شهادة WCAG رسمية | وصول غير موثّق خارجيًا | axe + فحص يدوي؛ تحسين مستمر |
| L-15 | لا توافق HIPAA/GDPR مُدّعى | لا امتثال قانوني | ضوابط تقنية فقط؛ مراجعة قانونية مطلوبة |

## 9. الترقية والتوافق الخلفي

| السيناريو | القاعدة |
|---|---|
| تثبيت جديد | Migration من `V001` ثم Seed مرجعي |
| ترقية 0.1.x → 0.1.y | Migrations إضافية فقط، بلا تعديل سابق |
| ترقية كبرى | نسخة احتياطية + Migration + Regression كامل |
| Rollback | استعادة نسخة + إعادة الإصدار السابق؛ لا Rollback جزئي للمخطط |
| تغيير الإعدادات | خارج الكود، بلا إعادة بناء |
| نقل لمستشفى آخر | إعدادات + Seed، بلا تغيير كود |

**سياسة الإصدار:** Semantic Versioning. أي تغيير يكسر API أو المخطط = Major.
