## 1. طريقة التقييم

كل ميزة تُقيَّم بأربعة أبعاد (1–5):

| البعد | المعنى |
|---|---|
| **V** Value | الأثر التشغيلي/السريري/المالي |
| **C** Complexity | جهد البناء والتكامل |
| **R** Risk | مخاطر السلامة/الخصوصية/سوء الاستخدام |
| **D** Data Readiness | جودة وتوفر البيانات اللازمة (5 = متوفرة ونظيفة) |

```
Priority Score = (V × 2) + D − C − R
```

- **≥ 8** ⇒ أولوية عالية (v1)
- **4–7** ⇒ أولوية متوسطة (Extended)
- **< 4** ⇒ مؤجّل أو مرفوض

**قاعدة حاكمة:** أي ميزة `R ≥ 4` لا تدخل v1 إلا بمراجعة بشرية إلزامية وحدود واضحة.

## 3. البطاقات التفصيلية — ميزات v1

### SF-01 — EMPI Scoring (مطابقة هوية المريض)

| العنصر | التفصيل |
|---|---|
| المشكلة | اسمان متشابهان ليسا نفس الشخص؛ والاسم وحده أسوأ معيار |
| الفكرة | تسجيل مرجّح: هوية وطنية (وزن 50) + تاريخ ميلاد (20) + هاتف (15) + اسم مطبّع (10) + جنس (5) |
| الخوارزمية | تطبيع عربي (إزالة التشكيل، أ/إ/آ→ا، ى→ي، ة→ه، مسافات) + Jaro-Winkler للاسم + مطابقة تامة للحقول الحساسة |
| النتيجة | `EXACT` ≥ 95 · `POSSIBLE` 70–94 · `NO_MATCH` < 70 (عتبات قابلة للتهيئة) |
| الحراسات | لا دمج تلقائي · `POSSIBLE` يتطلب سببًا وصلاحية · كل دمج قابل للتراجع بسجل |
| البيانات | `patients`, `patient_identifiers`, `patient_contacts` |
| القبول | TC-018/019: 20 زوجًا معروفًا (مكرر/ليس مكرر) بدقة ≥ 90% على مجموعة الاختبار |
| المرحلة | 3 |

## 6. ما لن أبنيه حتى لو طُلب (وسأشرح السبب)

| مرفوض | السبب |
|---|---|
| تشخيص آلي من الأعراض | ليس جهازًا طبيًا معتمدًا؛ خطر مباشر |
| اقتراح جرعة آلي | يتطلب تحققًا سريريًا وصيدليًا وقانونيًا |
| تغيير وصفة تلقائيًا | يخالف BR-PHR وBR-DEC |
| ترتيب أولوية الطوارئ آليًا | الفرز قرار بشري معتمد |
| دمج مرضى تلقائيًا | خطأ واحد يدمج سجلين مختلفين |
| إرسال أمر شراء تلقائي | التزام مالي يحتاج اعتمادًا |
| اتهام موظف من نمط شاذ | الأثر الجنائي/الإداري خارج نطاق النظام |
| عرض توقع بلا فاصل ثقة | يضلل الإدارة |
| ادعاء FHIR/HL7 compliant | لا يُدّعى قبل اختبار رسمي |
