# 05 — Monitoring & Operations

**ما لا يُقاس لا يُدار: مراقبة قابلة للتنفيذ، تشغيل يومي واضح، وحوادث بلا ارتجال**

| Field | Value |
|---|---|
| Document ID | DEP-OPS-001 |
| Version | 0.1 |
| Status | Approved (baseline 0.1) |
| Related | `01-server-architecture.md`, `04-backup-recovery.md`, `architecture/06-security-architecture.md`, NFR-OPS, NFR-REL-009 |

---

## 1. المبادئ

1. **كل تنبيه قابل للتنفيذ.** تنبيه بلا إجراء = ضجيج يُطفئ التنبيهات الحقيقية.
2. **الأعراض قبل الأسباب.** نبّه على «زمن استجابة مرتفع» و«مهمة فاشلة»، لا على كل قراءة CPU.
3. **الشفافية للمستخدم.** كل شاشة تعرض آخر تحديث وحالة البيانات.
4. **لا PHI في السجلات.** أسماء المرضى والهواتف والتشخيصات لا تُسجّل (NFR-PRV-003).
5. **كل حادث له مالك وقرار.** لا «سنرى لاحقًا».
6. **التشغيل موثّق.** أي إجراء متكرر له Runbook.

## 2. طبقات المراقبة

| الطبقة | ما يُراقب | الأداة |
|---|---|---|
| البنية | CPU، RAM، Disk، Network، UPS | node_exporter / OS |
| JVM | Heap، GC، Threads، Class loading | JMX / GlassFish |
| التطبيق | Latency، Error rate، Pool، Outbox، SSE | Health + Metrics |
| قاعدة البيانات | Connections، Slow queries، Locks، Buffer pool، Binlog | MySQL exporter / Performance Schema |

| الأمن | فشل دخول، Break-Glass، تعديل تدقيق | Security events |
| النسخ | نجاح/تأخر/حجم | Backup job |
| التحليلات | فشل المهام، تأخر اللقطات | `job_runs` |

## 3. المؤشرات والحدود

### 3.1 البنية

| المؤشر | تحذير | حرج | الإجراء |
|---|---|---|---|
| CPU (5 دقائق) | > 70% | > 85% | تحقق من الحمل/المهام |
| RAM متاح | < 15% | < 8% | تحقق من التسريب/الـ Heap |
| Disk `/` | > 70% | > 85% | تنظيف سجلات/أرشفة/توسيع |
| Disk `/var/lib/mysql` | > 70% | > 85% | أرشفة/توسيع |
| I/O Wait | > 10% | > 20% | فهارس/قرص أسرع |
| UPS | < 50% | < 20% | إيقاف آمن |
| NTP drift | > 1s | > 5s | تحقق chrony |

### 3.2 JVM / GlassFish

| المؤشر | تحذير | حرج | ملاحظة |
|---|---|---|---|
| Heap used | > 75% | > 90% | GC frequency |
| GC pause (P95) | > 500ms | > 2s | مراجعة الحجم/التسريب |
| Threads | > 80% من الحد | إشباع | تحقق من blocking |
| JDBC active | > 80% من 50 | إشباع | تحقق من تسريب |
| HTTP 5xx | > 0.5% | > 2% | افحص logs |
| P95 API قراءة | > 400ms | > 1s | NFR-PERF-001 |
| P95 API كتابة | > 1.2s | > 3s | NFR-PERF-002 |
| SSE connections | > 400 | > 600 | تحقق من التسريب |

### 3.3 قاعدة البيانات

| المؤشر | تحذير | حرج | ملاحظة |
|---|---|---|---|
| Connections | > 70% من 200 | > 90% | Pool/تسريب |
| Slow queries (>1s) | > 10/دقيقة | > 50/دقيقة | فهارس/استعلام |
| InnoDB lock waits | > 5/دقيقة | > 20/دقيقة | معاملات طويلة |
| Buffer pool hit | < 99% | < 95% | حجم الذاكرة |
| Binlog lag | > 5 دقائق | > 15 دقيقة | RPO |
| Replication (لاحقًا) | > 10s | > 60s | — |
| Deadlocks | أي | متكرر | مراجعة ترتيب الأقفال |

### 3.4 التطبيق والأعمال

| المؤشر | تحذير | حرج | ملاحظة |
|---|---|---|---|
| Outbox PENDING | > 100 | > 1000 | ADR-005 |

| DLQ | > 0 | متزايد | تحقيق فوري |
| KPI snapshot | فشل | يوم ناقص | تنبيه Analytics |

## 4. Health Endpoints

| المسار | المحتوى | الاستخدام |
|---|---|---|
| `/health` | `UP/DOWN` فقط | Load Balancer/Uptime |
| `/health/ready` | DB + JMS + Disk + Pool | النشر والمراقبة |
| `/health/live` | العملية حية | إعادة تشغيل تلقائي |

**قاعدة:** `/health` عام بلا تفاصيل. `/health/ready` داخلي فقط (NFR-REL-009).

## 5. السجلات (Logging)

| المسار | المحتوى | الاحتفاظ |
|---|---|---|
| Application | أخطاء، تحذيرات، أحداث عمل بلا PHI | 90 يومًا |
| Security | دخول، فشل، صلاحيات، Break-Glass | سنة |
| Medical Audit | `audit_logs` في DB | 7 سنوات |
| Access | `access_logs` في DB | 7 سنوات |
| Nginx | Access/Error بلا Query حساس | 30 يومًا |
| MySQL slow | استعلامات > 1s | 30 يومًا |
| Backup | نتائج النسخ | سنة |

**التنسيق:** JSON أو نمط موحّد، مع `timestamp`, `level`, `logger`, `trace_id`, `user_id` (اختياري)، `message`, `error_code`. لا نصوص مرضى.

**الدوران:** `logrotate`/journald مع حدود حجم. لا سجل بلا حد.

**الوصول:** السجلات للمسؤولين فقط؛ لا تُصدَّر إلى خارج الشبكة.

## 9. إدارة الحوادث

| الشدة | التعريف | أمثلة | الإشعار |
|---|---|---|---|
| **S1** | توقف كامل/فقد بيانات | DB down، فدية | فوري، كل الفريق |
| **S2** | وظيفة حرجة معطلة | صرف لا يعمل، دفع لا يُسجل | 15 دقيقة |
| **S3** | تدهور جزئي | بطء، تقرير فاشل | ساعة |
| **S4** | مشكلة بسيطة | خطأ عرض، إشعار مكرر | يوم عمل |

**خطوات:** اكتشاف → إعلان → عزل → تشخيص → إصلاح/التفاف → تحقق → إغلاق → Postmortem (S1/S2).

**Postmortem بلا لوم:** ما حدث، الأثر، السبب الجذري، ما نجح، ما فشل، إجراءات بتواريخ ومالكين.

## 10. إدارة التغيير

| البند | القرار |
|---|---|
| طلب تغيير | وصف + أثر + اختبار + تراجع + وقت |
| الموافقة | IT + المالك (وبالأمن إن لزم) |
| النافذة | خارج الذروة، بإشعار مسبق |
| الاختبار | DEV → TEST → STAGING → PROD |
| التراجع | حزمة سابقة + نسخة DB |
| التوثيق | سجل تغيير + تحديث Runbook |

**ممنوع:** تعديل مباشر على الإنتاج بلا طلب/نسخة/تراجع. لا `UPDATE` يدوي على بيانات سريرية/مالية.
