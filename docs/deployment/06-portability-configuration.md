# 06 — Portability & Configuration

**نفس الحزمة، مستشفى آخر: كل ما يخص المستشفى بيانات وإعدادات، لا كود**

| Field | Value |
|---|---|
| Document ID | DEP-PRT-001 |
| Version | 0.1 |
| Status | Approved (baseline 0.1) |
| Related | NFR-PRT-001..005, FR-SYS-001..006, `database/04-migrations-seed.md`, `architecture/02-backend-architecture.md` |

---

## 1. الهدف

نشر **نفس ملف EAR** في مستشفى آخر دون تعديل سطر كود، عبر:

1. إعدادات بيئة خارج الحزمة.
2. ملف تعريف مستشفى في قاعدة البيانات.
3. بيانات مرجعية قابلة للاستيراد.
4. قوالب قابلة للتحرير.
5. أعلام ميزات (Feature Flags).

**مقياس النجاح:** نشر ثانٍ ناجح في بيئة نظيفة خلال ≤ يوم عمل واحد، مع اختبارات دخان ناجحة (NFR-PRT-003).

---

## 2. طبقات الإعداد

| الطبقة | أمثلة | مكانها | من يغيّرها |
|---|---|---|---|
| **L1 — Build** | إصدار التطبيق، اسم الحزمة | `pom`/`build.xml` | المطوّر فقط |
| **L2 — Environment** | JNDI، اسم المضيف، مسارات، أسرار | متغيرات بيئة / `secrets.env` / GlassFish | IT |
| **L3 — Hospital Profile** | الاسم، الشعار، العملة، التوقيت، الترقيم | جدول `settings` + `branches` | مدير النظام |
| **L4 — Reference Data** | أقسام، خدمات، أسعار، أدوية، فحوصات، أدوار | Migrations/Seed | مدير النظام + المالك |
| **L5 — Templates** | طباعة، إشعارات، Order Sets، توثيق | `templates` | مدير النظام + المدير الطبي |

**قاعدة:** لا قيمة خاصة بمستشفى في الكود (NFR-PRT-001). أي `if (hospital == ...)` مرفوض في المراجعة.

## 3. إعدادات البيئة (L2)

| المفتاح | مثال | سري | ملاحظة |
|---|---|---|---|
| `SH_DB_JNDI` | `jdbc/smartHospital` | لا | يُقرأ من JNDI |
| `SH_BASE_URL` | `https://his.hospital.local` | لا | روابط الإشعارات |
| `SH_TIMEZONE` | `Asia/Amman` | لا | يُطابق `branches.timezone` |
| `SH_DEFAULT_LOCALE` | `ar` | لا | ar/en |
| `SH_SESSION_TIMEOUT` | `30m` | لا | مهلة الجلسة |
| `SH_UPLOAD_DIR` | `/opt/smart-hospital/files` | لا | خارج webroot |
| `SH_SMTP_HOST` | `mail.hospital.local` | لا | اختياري v1 |
| `SH_SMTP_USER` | `noreply@...` | نعم | في `secrets.env` |
| `SH_SMTP_PASSWORD` | — | نعم | في `secrets.env` |
| `SH_BACKUP_REPO` | `sftp:...` | نعم | لوكيل النسخ |
| `SH_FEATURE_FLAGS` | `ai.empi.enabled=true` | لا | يمكن تجاوزها من DB |

**الأسرار:** لا تُخزَّن في Git ولا في `settings`. تُقرأ من متغيرات بيئة/ملف بصلاحية 600. تدويرها موثّق.

## 4. ملف تعريف المستشفى (L3)

### 4.1 الحقول

| المجموعة | الحقول |
|---|---|
| الهوية | `hospital_name_ar`, `hospital_name_en`, `logo_path`, `address`, `phone`, `email`, `website` |
| قانوني/إداري | `license_no`, `tax_no`, `registration_no` (تُملأ من المستشفى، لا تُختلق) |
| العملة | `currency_code` (ISO 4217), `currency_symbol`, `decimal_places`, `rounding_mode` |
| الزمن | `timezone`, `date_format`, `time_format`, `week_start`, `fiscal_year_start` |
| اللغة | `default_locale`, `supported_locales`, `rtl_default` |
| الترقيم | `patient_no_format`, `invoice_no_format`, `receipt_no_format`, `visit_no_format` |
| الطباعة | `print_header_html`, `print_footer_html`, `paper_size`, `font_family` |
| الأمن | `password_min_length`, `password_history`, `lockout_threshold`, `lockout_minutes`, `session_timeout`, `mfa_required_roles` |
| Break-Glass | `bg_max_minutes` (≤ 60), `bg_requires_reason`, `bg_review_days` |
| البيانات | `retention_clinical_years`, `retention_financial_years`, `retention_audit_years` |
| الميزات | `features_json` (أعلام الميزات) |

### 4.2 قاعدة التحقق

- `currency_code` صالح ISO 4217؛ لا عملة بلا كود.
- `timezone` صالح IANA؛ لا `GMT+3` ثابت (يتعامل مع التوقيت الصيفي).
- `bg_max_minutes` بين 15 و60.
- `retention_*` ≥ الحد القانوني المحلي (يُعتمد من المالك).
- كل تغيير في `settings` يُسجّل في `audit_logs` (FR-SYS-006).

## 5. أعلام الميزات (Feature Flags)

| العلم | الافتراضي | الأثر | من يعتمد |
|---|---|---|---|
| `module.radiology.enabled` | false | إظهار الأشعة | المالك |
| `module.ors.enabled` | false | غرف العمليات | المالك |
| `module.hrm.enabled` | false | الموارد البشرية | المالك |
| `module.integration.enabled` | false | طبقة التكامل | المالك |
| `ai.empi.enabled` | true | اقتراح تكرار المرضى | مدير السجلات |
| `ai.interactions.enabled` | true | تحذير التفاعلات | الصيدلي + المدير الطبي |
| `ai.ews.enabled` | false | تنبيه التدهور | المدير الطبي |
| `ai.forecast.enabled` | false | التوقعات | مدير التحليلات |
| `ai.anomaly.enabled` | false | كشف الشذوذ | مسؤول الجودة |
| `ai.decision_cards.enabled` | false | بطاقات القرار | المالك |
| `security.mfa.enabled` | false | MFA للأدوار الحساسة | مسؤول الأمن |
| `security.break_glass.enabled` | true | وصول طارئ | مسؤول الأمن |
| `notifications.sse.enabled` | true | تحديث فوري | IT |
| `print.arabic.enabled` | true | طباعة عربية | المالك |

**قاعدة:** كل علم له مالك وقيمة افتراضية وسبب. لا علم يفعّل ميزة محظورة (R0). التغيير يُسجّل ويُبلّغ.

## 6. البيانات المرجعية (L4)

| الحزمة | المحتوى | إلزامية | ملاحظة |
|---|---|---|---|
| `S001` | أدوار وصلاحيات | نعم | R-01..R-18 |
| `S002` | خدمات وأسعار مبدئية | نعم | تُعدّل محليًا |
| `S003` | فحوصات مختبر | نعم | كتالوج مصغّر |
| `S004` | أدوية | نعم | بلا تفاعلات مرخّصة |
| `S005` | قوالب + KPIs + قواعد قرار | نعم | تعريفات لا أهداف |
| `S006` | بيانات وهمية للعرض | **لا** | DEV/STAGING فقط |
| `S007` | أقسام/عيادات/أجنحة/أسرة | نعم | حسب المستشفى |
| `S008` | أيام عمل/عطل | نعم | حسب المستشفى |
| `S009` | مستخدمون أوليون | نعم | كلمات مرور تُغيّر فورًا |

**قواعد:**
- كل Seed Idempotent (لا تكرار عند إعادة التشغيل).
- لا أسعار/أسماء مرضى/أطباء حقيقية في الحزم العامة.
- البيانات المحلية تُوثّق في `docs` المستشفى لا في الكود.
- أي تعديل يدوي على مرجع يُسجّل في التدقيق.

## 7. القوالب (L5)

| النوع | مثال | محرك | نسخة |
|---|---|---|---|
| طباعة | فاتورة، إيصال، تقرير مختبر، ملخص خروج | HTML/CSS + خط عربي مضمّن | `version_no` |
| إشعارات | عنوان/نص AR/EN | Placeholders | `version_no` |
| توثيق | ملاحظة SOAP، ملخص | حقول قابلة للتهيئة | `version_no` |
| Order Sets | «اشتباه سكري» | بنود قابلة للتعديل | `version_no` |
| قوالب سريرية | تحقق الحد الأدنى | حقول إلزامية | `version_no` |

**قاعدة:** القالب المعتمد لا يُعدّل مباشرة؛ يُنشأ إصدار جديد ويُعتمد. الطباعة تستخدم الإصدار الساري وقت الحدث.

## 8. ما يمكن تهيئته وما لا يمكن

| يمكن تهيئته | لا يمكن بدون كود |
|---|---|
| الأسماء، الشعار، العملة، التوقيت | مسار سريري جديد كليًا |
| الأقسام، العيادات، الأسرة | وحدة جديدة (مثل Blood Bank) |
| الخدمات والأسعار | تغيير مخطط قاعدة البيانات |
| الأدوار والصلاحيات | منطق مالي/سريري جديد |
| عتبات التنبيه وEWS | بروتوكول تكامل جديد (HL7/DICOM) |
| قوالب الطباعة والإشعارات | خوارزمية مطابقة جديدة |
| أعلام الميزات | تجاوز قواعد السلامة |
| حدود KPIs وأهدافها | تعريف KPI غير موجود |
| ساعات العمل والعطل | Multi-tenant حقيقي |

**قاعدة:** أي طلب «تهيئة» يغيّر منطقًا = Change Request + ADR + اختبارات، لا إعداد.

## 9. دعم الفروع (Branches)

- v1: مستشفى واحد، وفرع واحد أو أكثر داخل نفس الكيان.
- `branch_id` موجود في الجداول الرئيسية (NFR-SCL-004).
- المستخدم قد يرى فرعًا أو أكثر حسب النطاق.
- التقارير تُصفّى بالفرع.
- **Multi-tenant (عدة مستشفيات في DB واحدة) غير مدعوم في v1**؛ يتطلب عزلة وتشفيرًا وتصميمًا منفصلًا.
