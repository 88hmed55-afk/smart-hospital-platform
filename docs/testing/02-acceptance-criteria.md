## 1. الغرض والنطاق

### 1.1 الغرض

تحويل كل متطلب إلى **حالة قبول واحدة على الأقل** قابلة للتنفيذ والقياس، بحيث يمكن:

1. إثبات التغطية الكاملة أمام المراجع الأكاديمي.
2. منع "الاكتمال الوهمي" (شاشة موجودة، منطق ناقص).
3. إعادة تنفيذ الاختبارات نفسها بعد أي تغيير (Regression).
4. ربط كل عيب بمعيار قبول واضح.

### 1.2 داخل النطاق

- 166 FR في 20 نطاقًا، مع الأولويات M/S/C.
- C1–C12 (تزامن) وTC-167..TC-178.
- OWASP Top 10 الأساسي وTC-179..TC-187.
- النسخ/الاستعادة/إعادة التشغيل وTC-188..TC-189.
- العربية RTL والطباعة وTC-190.

### 1.3 خارج النطاق

- اختبار اختراق رسمي معتمد، أو شهادة WCAG، أو اختبار أجهزة طبية.
- اختبار سحابي أو HA متعدد الخوادم (خارج v1).
- اختبار وحدات Future كوظائف إنتاجية؛ تُختبر فقط كعقود تصميم عند الحاجة.

## 2. اصطلاحات التنفيذ

### 2.1 نوع الحالة

| الرمز | المعنى | مثال |
|---|---|---|
| **P** | مسار إيجابي (Happy Path) | تسجيل مريض صحيح |
| **N** | مسار سلبي/ممنوع | رفض صرف دفعة منتهية |
| **B** | قيمة حدّية | كمية = 0 أو الحد الأقصى |
| **C** | تزامن | صرفان لنفس الدفعة |
| **S** | أمن | IDOR أو CSRF |
| **R** | تعافٍ/تشغيل | استعادة نسخة |
| **U** | قابلية استخدام/وصول | RTL ولوحة مفاتيح |

### 2.2 نتيجة التنفيذ

| النتيجة | التعريف |
|---|---|
| **PASS** | كل الخطوات نُفّذت والنتيجة الفعلية = المتوقعة، مع دليل |
| **FAIL** | فرق واحد على الأقل، مع عيب مسجّل |
| **BLOCKED** | شرط مسبق غير متحقق (بيئة/بيانات/اعتمادية) |
| **NOT RUN** | لم تُنفّذ بعد (الوضع الحالي لكل الحالات) |

### 2.3 الدليل المطلوب

- لقطة شاشة أو تسجيل للواجهة عند الحالات المرئية.
- استجابة HTTP (Status + Body مختصر) للحالات السلبية.
- استعلام تحقق DB قبل/بعد للعمليات المالية والسريرية.
- Trace ID أو معرّف السجل في `audit_log` عند الادعاء بوجود تدقيق.

### 2.4 قاعدة البيانات المسبقة

| البند | القيمة |
|---|---|
| بيانات مرجعية | فرع واحد، قسمان، عيادتان، 10 أسرة، 20 خدمة، 30 دواءً، 20 فحصًا |
| مستخدمون | مدير نظام، مدير مستشفى، استقبال، طبيب، ممرض، فني مختبر، صيدلي، مالية، مخزون، مدقق |
| مرضى | 3 مرضى على الأقل: بالغ، طفل، مريض بحساسية دوائية |
| زيارات | زيارة مفتوحة، زيارة مغلقة، زيارة طوارئ، تنويم نشط |
| بيانات مالية | فاتورة غير مدفوعة، فاتورة جزئية، فاتورة مدفوعة، وردية مفتوحة |
| بيانات ذكية | 12 شهرًا من اللقطات اليومية لاختبار KPI والتوقعات |

| TC-188 | استعادة نسخة كاملة + PITR | نسخة Full + Binlog → استعادة على خادم نظيف → تشغيل التطبيق → فحص الأعداد وسلسلة التدقيق | RPO ≤ 15 دقيقة؛ RTO ≤ 4 ساعات؛ الأعداد والعلاقات صحيحة؛ سلسلة التدقيق سليمة؛ تسجيل الدخول يعمل |
| TC-189 | إعادة تشغيل/انهيار الخادم | قتل GlassFish/MySQL أثناء دفع وصرف → إعادة التشغيل → فحص الحالة | لا معاملة نصف مكتملة؛ Outbox يستأنف؛ الجلسات تُعاد؛ `/health` أخضر خلال 10 دقائق؛ لا فقد بيانات |

**ملاحظة:** تُنفّذ TC-188 على نسخة إنتاجية مجهولة الهوية أو على STAGING مطابق، وليس على الإنتاج مباشرة.

## 8. معيار العربية RTL والطباعة (TC-190)

| البند | معيار النجاح |
|---|---|
| الاتجاه | كل الشاشات العربية RTL، والإنجليزية LTR، بلا انعكاس في الأيقونات أو الأرقام |
| الخط | خط عربي مضمّن (Noto Naskh/Cairo) يعمل بلا إنترنت |
| التنقل | كل الوظائف الحرجة قابلة للوصول بلوحة المفاتيح، وتركيز مرئي، وترتيب Tab منطقي |
| قارئ الشاشة | تسميات ARIA للحقول والجداول والأزرار الحرجة؛ لا صورة بلا نص بديل |
| التباين | يطابق WCAG AA للعناصر الأساسية |
| الطباعة | فاتورة + إيصال + تقرير مختبر + كشف مواعيد: بلا قطع، بلا تداخل، الهوامش والأعمدة سليمة |
| الباركود | يُطبع ويُمسح ضوئيًا؛ يحتوي `public_id` فقط |
| الأداء | الطباعة تبدأ خلال 3 ثوانٍ على LAN |

## 10. شروط الدخول والخروج

### 10.1 شروط دخول أي دورة قبول

- [ ] الوثيقة المعتمدة للمتطلب موجودة (FR + BR + TC).
- [ ] البناء ناجح وMigrations تعمل على قاعدة نظيفة.
- [ ] بيانات الاختبار المطلوبة محمّلة.
- [ ] الصلاحيات والأدوار المضبوطة.
- [ ] لا عيب S1 مفتوح يمنع التنفيذ.

### 10.2 شروط الخروج النهائي

- [ ] 190/190 حالة منفّذة (PASS/FAIL/BLOCKED مسجّلة).
- [ ] ≥ 95% PASS، وكل FAIL غير حرج له خطة وتاريخ.
- [ ] 0 عيب S1/S2 مفتوح.
- [ ] كل حالات `M` ناجحة.
- [ ] TC-167..TC-178 ناجحة بالكامل.
- [ ] 0 ثغرة Critical/High.
- [ ] RPO/RTO محققان في تمرين موثّق.
- [ ] UAT موقّع.
- [ ] التغطية الحرجة ≥ 70%.

### 10.3 قواعد إعادة الاختبار

| التغيير | ما يُعاد اختباره |
|---|---|
| تعديل خدمة/معاملة | TC المرتبط + TC تزامن ذلك المسار + Regression للوحدات المعتمدة |
| تعديل مخطط DB | كل TC يمس الجدول + Migration + استعادة |
| تعديل صلاحية | TC-011/012 + TC الخاص بالشاشة + IDOR |
| تعديل واجهة | TC-190 + E2E للسيناريو |
| ترقية GlassFish/MySQL | كل TC + الأداء + التعافي |
